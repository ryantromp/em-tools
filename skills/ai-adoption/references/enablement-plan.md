# Whole-team enablement menu

Pick 3 to 5 items that fit the findings. Offer them to everyone; never target named people. Make taking part optional, and never tie it to reviews.

| If the team data shows | Offer |
|---|---|
| Low or flat adoption | A 45-minute show-and-tell where volunteers demo one real task; shared prompt and workflow notes in the team wiki |
| Uneven spread of active days | Pairing hour once a week, open to anyone; a short "getting started" guide for the team's own stack |
| Larger PRs since rollout | Team agreement on PR size (for example under 300 lines) whatever tool wrote the code; tool settings or prompts that ask for small changes |
| More review comments or review time | A review checklist for AI-assisted changes; protected review slots; rotate reviewers so load is shared |
| Higher revert or churn rate on AI-assisted changes | Require tests in the same PR; a "verify before merge" checklist; retro on two recent reverts, blameless |
| Low trust in output | A team session on when not to use the tools (security-sensitive code, unfamiliar domains); share failure examples openly |
| Spend rising faster than use | Review seat allocation with the team; turn off unused seats; agree usage-based limits |

Measure the effect at team level only, after 6 to 8 weeks.
